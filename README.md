# CareLoop

A menstrual migraine self-care companion prototype with deterministic recorded-pattern analysis and an optional Tencent Cloud ADP explanation.

## Run locally

1. Install Node.js LTS (v20+), then run `npm install`.
2. Copy `.env.example` to `.env` and set `ADP_APP_KEY` to the AppKey for the published CareLoop Insights agent. Keep this file local; `.env` files are Git-ignored.
3. In one terminal, run `npm run server`.
4. In a second terminal, run `npm run dev` and open the local URL printed by Vite.

Vite proxies `/api` requests to the local server at `127.0.0.1:8787`. To verify the connection, open **AI Insights**, click **Generate AI Explanation**, and confirm that the result is labelled as generated by Tencent Cloud ADP. The browser sends aggregate synthetic counts only; the AppKey is added by the server and is never returned to the browser.

In development, the backend logs safe connection diagnostics: local route, credential presence as a boolean, upstream HTTP status/content type, SSE event types, and failure category. It never logs the AppKey, prompt, aggregate facts, or complete request bodies. Set `ADP_DIAGNOSTICS=disable` to turn these messages off. If `.env` or `ADP_APP_KEY` is missing, the backend still starts and returns a structured `MISSING_CREDENTIALS` response so the UI can show its safe fallback.

## AI endpoint safeguards

`/api/insights` defaults to 5 requests per IP per hour, 2 simultaneous Tencent ADP calls, and 50 upstream attempts per UTC day. Configure these with `ADP_RATE_LIMIT_PER_HOUR`, `ADP_MAX_CONCURRENT`, and `ADP_DAILY_REQUEST_LIMIT`. An upstream attempt is reserved before Tencent is called, so failures, timeouts, and rejected model output still consume daily capacity. Invalid and failed-authentication requests consume the per-IP allowance.

Set `ADP_DEMO_PASSWORD` to a long random value to require shared demo access. The password uses HTTP Basic authentication and must only be used over HTTPS. It is entered at runtime, held in page memory, and is never included in the frontend bundle. Set `ADP_TRUST_PROXY=true` only when a trusted hosting proxy overwrites `X-Forwarded-For`; otherwise clients could spoof their rate-limit identity.

These counters are intentionally in memory for a single-instance hackathon demo. They reset whenever the process restarts and are not shared between multiple server instances. Before any public deployment, configure an independent Tencent Cloud request quota or spending safeguard; the application counters are not a billing boundary.

Run `npm test` for the deterministic and mocked-ADP tests. To check the production frontend build, run `npm run build`.

## Render production setup

Use one Render **Web Service** for this project. The Node process serves both the compiled Vite frontend and `/api/insights`, so no production Vite proxy or separate static site is required. If the repository contains the app in the `careloop` subdirectory, set Render's root directory to `careloop`.

- Build command: `npm ci && npm test && npm run build`
- Start command: `npm start`

`npm start` does not require a `.env` file. Set these values in Render's environment settings:

- `NODE_ENV=production`
- `ADP_APP_KEY` to the published agent key (secret and required)
- `ADP_DEMO_PASSWORD` to a long random demo password (secret and strongly recommended)
- `ADP_RATE_LIMIT_PER_HOUR=5`
- `ADP_MAX_CONCURRENT=2`
- `ADP_DAILY_REQUEST_LIMIT=50`
- `ADP_TRUST_PROXY=false`

Render supplies `PORT`; do not hardcode it. In production the server uses `PORT` before `ADP_PORT` and binds to `0.0.0.0`. Locally, `npm run server` still loads `.env`, uses `ADP_PORT` (default `8787`), and binds only to `127.0.0.1`.

Keep `ADP_TRUST_PROXY=false` on Render. The socket address will generally identify Render's proxy, so multiple visitors can share the same in-memory per-IP bucket and one visitor can temporarily throttle others. This is conservative for cost protection. Enabling the current option reads the leftmost `X-Forwarded-For` value, which must not be trusted unless the entire proxy path is independently verified to overwrite caller-supplied values. For a larger or multi-instance deployment, replace this mechanism with an edge or shared-store limiter based on a platform-verified client identity.

The existing daily, concurrency, and per-IP counters remain process-local: they reset on restart and are not shared across instances. Run exactly one instance for this demo and configure an independent Tencent Cloud quota or spending safeguard before making it public.

## Scope

Every patient and health detail shown in the interface is fictional and labelled as synthetic demonstration data. The AI receives only whitelisted aggregate results from the deterministic analysis; it does not calculate statistics or receive raw diary records. Its output is optional, validated, and falls back to the deterministic summary on failure. It must not be used for diagnosis or medication advice.
